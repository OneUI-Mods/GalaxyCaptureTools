# Galaxy Capture Tools 開発記録

対象: Galaxy SM-S948Q / Android 16 / One UI 8.5。Smart Capture 6.1.76.9。
既存のGalaxy Adaptive Barとは別アプリ・別リポジトリで開発する。

## 要求

1. 動画の開始時の幅・高さを固定し、端末の回転差に応じて映像を90度回転。横長映像を縦動画へ縮小して入れる黒帯を解消する。
2. AOSP Android 14 QPR2のアプリ単位録画・標準アプリ選択へ準拠し、Galaxy録画でも利用する。
3. 追加オプションとして、タスクの切替先Activity全体へ追従せず、選択時の1つのウィンドウへ固定する。
4. それぞれON/OFF。Material 3、多言語、クラッシュ保護、release署名配布。

## 確認した実装

- Galaxy録画のMP4RecorderもMediaProjectionを使用する。semGetMediaProjectionからprojectionを作り、固定寸法のVirtualDisplayへ投影する。onCapturedContentResizeは何もしない。
- SystemUIにAOSP系MediaProjectionAppSelectorActivityが存在する。標準のLaunchCookieとtaskIdを返し、IMediaProjectionへ設定できる。
- ContentRecorderはSurfaceControlのmirrorへ等比縮小と中央配置を適用する。ここで回転差に応じた座標変換を適用すれば、再エンコードや毎フレームのCPUコピーなしで対策できる可能性がある。
- AOSPのタスク単位録画を基準に、固定ウィンドウは追加の制約として扱う。保護画面のフラグ・secure layer・MediaProjectionの同意や停止処理は維持する。

## 音声の検証素材

`-PcaptureFixtures`でのみ別UIDの880Hz音声テストAPKをビルドする。アプリ本体へは依存させず、配布手順にも含めない。androidTest側の映像fixtureはtone=trueで440Hzを再生する。対象のみで440Hz、端末全体で440Hzと880Hzの両方を収録できることをスペクトルで比較する予定。別UIDの音は60秒で自動停止する。

SamsungのDisplayManagerServiceは通常の逆コンパイル結果で条件が逆転していた。fallbackの分岐を確認し、launch cookieが存在する場合にcreateTaskSessionへ進むことを確認した。

## 対象一覧の実機修正

ログからActivityRecord.findMainWindowの引数不一致を確認。このビルドにはfindMainWindow(boolean)だけが存在するため、一覧取得・固定対象の初期化・再生成時の取得をすべてfalse付きへ統一した。元の無引数呼び出しでは一覧取得が中止されていた。

## Samsung実機で確認できた動作

- findMainWindow(false)への修正後、開始画面の対象一覧取得・検索・明示選択・カウントダウンからのアプリ録画に成功。dumpsysで対象TaskとUIDを確認した。
- 同一TaskのFixture Aから赤一色のFixture Bへ遷移。アプリ録画の96フレーム中36フレームにBを確認。ウィンドウ録画は18フレームすべてにBを含まず、選択ウィンドウの表示を保持した。Samsungは静止画面を可変フレーム間隔で保存するため、解析では指定時刻以前の最後のフレームを調べる。
- 別UIDの880Hzサービスが動作中の比較を行った。端末全体では440Hzと880Hzのピークが約719、対象のみでは440Hzが約719、880Hzは0.003未満。対象の音声を残したまま別アプリの音声を除外できた。
- 一覧取得中に検索すると、応答後にフィルターがリセットされる問題を発見。検索文字列を状態に保持するよう修正した（Samsung側の再起動のみで反映可能）。

## 固定ウィンドウの回転中の再生成

Android標準のタスク録画＋ウィンドウ固定＋回転で、WindowStateのフレームが一時的に空になり、Empty recording geometryによって保護停止することを実機で検出した。空の期間は投影を隠し、同じActivityRecordのメインウィンドウの再レイアウトを待つ。以後のsurface配置で有効な寸法へ戻った時だけ座標変換を再適用する。別Activityへ対象を差し替えることはしない。保護停止後のセッション終了が「Ready」で上書きされる表示も修正した。

## 修正版の最終確認

- Android標準のタスク録画＋固定ウィンドウで縦→横→逆横を実施。録画は継続し、同じ90度補正を保持。保存動画の横向きの四隅に色付きの映像が入り、同一アプリの別Activityへ移ると黒画面へ移行した。別UIDの880Hz再生中でも、440Hzが約508、880Hzは0.003未満だった。
- Galaxyの固定ウィンドウでも縦→横→逆横を実施。1080×2340を保持し、横・逆横とも同じ四隅の並びを確認。保護停止は発生しなかった。
- 横開始・黒帯補正OFF・180度無視ONでGalaxy録画を実施。2340×1080で持ち替え前後の四隅が一致した。
- 設定画面の全体OFF、設定値の保持、黒帯補正OFF中でも180度設定を操作できることのinstrumentationを再実行し成功（1件）。20件の単体テストとLintも成功。
- 内部の映像fixture、別UIDの音声fixture、コンソール用dexと一時スクリーンショットを実機から除去した。録画データは削除しない。機能設定は検証前の値へ戻し、録画が終了していることを確認。
- 指定ウィンドウのroot surfaceを投影するため、付属する子ウィンドウまで分離する方式ではない。保護フラグの継承を崩すbuffer layerへの単純な差し替えは行わない。付属ポップアップの制限を利用者向け資料にも記載した。

## 0.1.3: スピーカー時のマイクのみ分岐、自動起動

Samsung EnhancedMicAudioRecorderは、イヤホン・PS通話・マイクミュート以外では再生側PCMを混ぜず、マイクの音だけを出力していた。独自PCMミキサーは導入しない。既定ONのspeaker_mediaで、標準混音callbackの間だけMP4Recorder.isPluggingの戻り値をtrueにし、標準の内部音声＋マイク分岐を使う。対象ownerとの参照一致とThreadLocalで限定し、別スレッド・別レコーダーには作用させない。afterHookで例外時も前のcontextを復元する。音量・飽和処理・チャンネル・エンコーダー・バッファ・時刻・実際のルートは一切変更しない。app-only／全音声どちらにも適用する。

OFFの場合はSamsungの原処理をそのまま使う。開始ダイアログの既存音声ラベルはスピーカー出力中のみ「マイクのみ」へ変更し、実際のSamsungの出力先判定に追従する。選択値やアイコン、既存の音声設定は書き換えない。表示中だけルート・マイクミュートの通知を受け、閉じたら解除する。

2本ともRECEIVE_BOOT_COMPLETEDの非公開・directBootAware receiverを追加。ロック中はCE設定へアクセスせず、BOOT_COMPLETEDとMY_PACKAGE_REPLACEDで設定を通知する。Activity起動・サービス・suを使わない。SystemUI／Samsung／frameworkの初期設定取得は、解錠イベントと上限付きの遅延再試行で復帰する。クラッシュ保護の解除やONへの強制変更は行わない。

独立したAndroid 16 Play Storeイメージ（ro.debuggable=0）を再起動し、両アプリのBootReceiverがプロセスを自動起動したことをActivityManagerログで確認。起動設定維持を含む画面テストはBar8件、Capture4件成功。レコーダー・スレッド・入れ子・例外終了の混音context隔離テスト4件を含め、単体テスト24件成功。設定スイッチ更新後の画面テスト2件も成功。Galaxy音声録画・イヤホン抜き差し・AOSP混音と、ソフトリブート後の復帰は実機確認中。


## libxposed API 102への移行

API 82のcompileOnly JAR、legacy manifest metadataとassets/xposed_initを除去。io.github.libxposed:api:102.0.0をcompileOnlyで使用し、XposedModuleのonModuleLoaded／onPackageReadyとframeworkのonSystemServerStartingで初期化する。META-INF/xposed/module.prop、java_init.list、scope.listを登録。min/target APIは102、autoHotReload=false。system_serverのscope名はmodern仕様のsystem。

既存のbefore/after処理は自前のHookCallbackでAPI 102のChainへ適応する。実登録はhook(Executable).setId(...).intercept(...)、解除は所有するHookHandleのみ。明示的な録画拒否・例外を握り潰さないようPASSTHROUGHを設定し、before/after自体の例外は原処理の結果を維持する。共有のReflectは通常のJava reflectionをキャッシュし、legacy APIへ一切依存しない。Batteryのdeoptimizeも公開APIへ変更した。

引数変更、戻り値、原処理の省略、意図した拒否、例外とcleanup、反射のオーバーロード・継承・静的呼び出し、登録失敗時の部分解除を回帰テストする。配布チェックはmodern metadataと旧APIの混入を検査。ライセンス一覧のcompile-only参照も102へ更新した。

API 102向けの単体テストはbefore/after adapter・反射・登録解除の15件を含む。rootなしのAndroid 16エミュレーターで起動・設定・ライセンス画面が起動し、UIテストBar8件／Capture4件成功。最初のBar実行はADBサーバー側の接続断で途中終了し、残り7件を再実行して成功。


## 音声・自動復帰・API 102の最終実機確認（0.2.0）

Samsungのアプリ対象・対象UIDの音声・メディアとマイクで実録画。speaker_media=ONではイヤホン接続／切断後も440Hzが継続した。OFFではスピーカー時の表示が「マイクのみ」、イヤホン接続時は「メディアとマイク」へ戻った。OFF録画は接続中に440Hzを維持し、切断後はその成分が低下してマイク収録が続いた。Samsung標準の48kHz stereo AACを保持し、独自PCMミキサーは含めない。ON/OFFの録画はそれぞれ13.36秒／73.6秒。保存は非同期のため、新しいファイル名の確定後に取得した。

Android標準のアプリ対象・MIC_AND_INTERNALを実録画。別UIDの880Hzを並行再生しても対象440Hzが約508、880Hzは0.051未満で、マイクも有効だった。44.1kHz mono AACという標準の形式を維持する。AOSPのworkerは内部音声とマイクを混ぜ、Samsungのスピーカー時のみマイクにする分岐は存在しない。独自のゲイン・追加バッファを導入していない。主観的な遅延比較や全音声機器の品質保証までは行っていない。

API 102版の署名済みreleaseを既存アプリへ上書きしてソフトリブート。解除後、設定画面を開く前にframework／SystemUI／SamsungがReadyへ復帰し、Vectorのmodern loaderとAPI登録を確認。Samsungの別画面の対象一覧・選択・開始・保存と、Android標準の対象Task録画・保存を再確認した。Samsungは4.22秒の対象アプリ録画と追加の全画面録画、AOSPは7.45秒の対象アプリ録画を保存した。対象Task／UIDはdumpsysで一致。AOSPは440Hzが約1522、880Hzは0.004未満だった（追加の別UID音はこの短い再試験では再生していない）。Samsungは標準の録音音量係数に従うため、メディア音量0では内部音声も低下する。音量7で440Hzを収録した。両ホストとframeworkに保護停止・例外はなかった。

## 0.2.1: 操作UIの除外・録画バー非表示・カウントダウン

FloatingButtonView.initViewとガイドpopup、ServiceFragmentForStandAloneのregisterUiの間だけThreadLocalで作成対象を限定。Samsungプロセス内のWindowManagerGlobal.addViewの直前に、対象rootのLayoutParamsへPRIVATE_FLAG_IS_ROUNDED_CORNERS_OVERLAY（0x100000）を付ける。対象firmwareのWindowStateAnimator.createSurfaceLockedは、このprivate flagからSurfaceControl.SKIP_SCREENSHOT（0x40）を生成時に付与する。表示後の非同期transactionやSamsungのinternal-presentation-only metadataの後付けを使わず、最初のsurfaceから除外する。FLAG_SECUREへ変更しない。

非表示時も純正Viewの作成とcallbackを維持し、window alpha=0とNOT_TOUCHABLE／NOT_FOCUSABLEに限定。native Viewのalphaアニメーションではwindow alphaが戻らない。WMのupdateViewLayoutにも同じpolicyを維持する。WeakHashMapでrootごとに保持し、回転再描画は同じrecorderのpolicyを継承。設定は次の録画／スクリーンショットから反映。カメラ・annotationや画面の一部の編集用rootには適用しない。スクロールキャプチャ側の合成処理と保存処理も変更しない。

カウントダウンOFFでは、純正startCountDownTimerが設定したCountDownTimerを同じmain-thread呼び出し内でcancelし、そのtimerのonFinishを一度実行する。標準callbackがprogress timer/taskとviewを破棄し、操作バーを生成してstartRecordingする。対象選択・同意の未完了時にはtimerがないため開始しない。新しい常駐timerや別の録画開始経路を追加しない。

単体テスト44件とLint成功。master／guardの無効時、スクリーンショットUIの表示・入力維持、非表示時の入力通過、既存flags維持と繰り返しrelayoutを検証。修正前の連続スクリーンショットでは操作バーとサムネイルの映り込みを再現した。署名済みrelease版を既存環境へ上書きし、Samsungキャプチャのみ読み込み直して比較した。

## 0.3.0: キャプチャ制限の個別設定・録画音量・Samsung設定統合

- source windowのFLAG_SECUREを変更せず、SystemUIの同期スクショ要求と、既存の録画承認を経た2種類の録画用VirtualDisplayだけを対象にする。第三者のcast、Recents、shellのscreencapには引き継がない。
- screenshotはWmScreenshotControllerのrequest scope内だけでsecure-layer captureを許可する。native失敗理由16のみを解除し、敏感なコンテンツやDPMの判定を維持する。録画はDMS BinderServiceの所有UID・package・録画display名・projectionの一致を検査し、当該同期要求内だけSECURE display bitを追加する。
- Samsungの録画用事前スクショがnullの場合は、録画専用scope内だけ非保存probeへ置換する。電池・ストレージ・通話・承認フローを省略しない。
- AudioLevelsはnative PCMの有効サンプルに0–100%の減衰のみを適用。キュー、リサンプリング、別AACエンコーダを追加しない。EnhancedMicのdevice-volume tableだけを同一recorder/mix callback内でunityに置換し、native route/call/mute/clippingとUID別AudioPlaybackCaptureConfigurationは維持する。各audio recorderで開始時の設定を保持する。
- Samsungの:settings processにあるSettingsFragmentへホストのSESL SwitchPreferenceCompat/SeekBarPreferenceを挿入する。設定はmodule providerの同じallowlist・SharedPreferencesで管理し、native側とmodule側の表示も設定変更通知で更新する。初期化時は書き込まない。
- captureの同期処理はHostGuardの操作カウンタで囲み、既存録画のactive状態を上書きしない。
